# rec_pytorch

Захват и сопровождение целей на RTSP-потоке камеры. Нейросеть YOLOv8 (PyTorch) находит цели,
трекер ByteTrack ведёт их от кадра к кадру под постоянными номерами, а всё, что произошло,
записывается в ClickHouse: события, итоги по каждой цели и траектории движения. В момент захвата
цели делается снимок.

По умолчанию сопровождаются люди, но можно выбрать любые из 80 классов COCO (машины, животные и т. д.).

## Что значит «захват» и «сопровождение»

```
кадр > детектор + трекер > реестр целей > снимок, ClickHouse, журнал
```

* **Обнаружение.** Детектор увидел цель, трекер дал ей номер. Пока цель не подтверждена, о ней
  никто не узнаёт: случайные ложные срабатывания не попадают ни в базу, ни в снимки.
* **Захват.** Цель подтверждена на `confirm_hits` кадрах подряд. В этот момент делается снимок
  (с рамками и номерами) и пишется событие `captured`.
* **Сопровождение.** Пока цель в кадре, копится статистика (сколько кадров, уверенность, пройденный
  путь) и раз в `points_interval_sec` секунд пишется точка траектории. Если цель на секунду
  скрылась за препятствием, она сохраняет свой номер и захват не повторяется.
* **Потеря.** Цель не видна дольше `lost_timeout_sec`. Пишется событие `lost` и итоговая строка
  по цели. При остановке программы итог пишется по всем ещё сопровождаемым целям (причина
  `shutdown`).

## Как устроено

Три потока, чтобы медленная нейросеть не тормозила ни видео, ни запись:

1. **Чтение камеры** хранит только самый свежий кадр. Буфер декодера не копится, задержка не растёт.
2. **Сопровождение** берёт свежий кадр, прогоняет его через YOLOv8 + ByteTrack и передаёт результат
   реестру целей, а тот вызывает снимок и запись.
3. **Запись в ClickHouse** копит строки в памяти и отправляет пачками. Если база недоступна, строки
   ждут в буфере (не больше `max_buffer_rows`), а сопровождение продолжает работать как ни в чём не бывало.

Окно с видео (если не указан `--headless`) рисует рамки, номера и «хвосты» траекторий в главном потоке.
Захваченные цели обведены толстой рамкой, ещё не подтверждённые тонкой.

## Установка

Необходим Python 3.12 или новее.

Быстрый путь на Windows: скрипт ставит пакеты в `venv`, создаёт `.env` со случайным паролем,
поднимает ClickHouse в Docker, создаёт таблицы, делает самопроверку и прогоняет тесты:

```
powershell -ExecutionPolicy Bypass -File .\setup_dev.ps1
```

Вручную:

```
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

По умолчанию ставится PyTorch для CPU. Этого достаточно: модель `yolov8n` на современном
процессоре обрабатывает кадр примерно за 30-50 мс (около 25 кадров/с).

### Видеокарта Nvidia (необязательно)

Сначала необходимо поставить PyTorch с CUDA. Команда для нужной версии CUDA приведена на
<https://pytorch.org/get-started/locally/>, она выглядит так:

```
pip install torch torchvision --index-url https://download.pytorch.org/whl/cuXXX
```

Затем установить остальное (`pip install -r requirements.txt`), указать в `config.toml`
`device = "cuda"` и проверить, что видеокарта видна:

```
python main.py --self-test
```

В выводе должно быть `CUDA доступна: True`. Если в конфигурации `device = "cuda"`, а CUDA
недоступна, программа сразу сообщает об этом понятной ошибкой.

## Настройка

```
copy config.example.toml config.toml
```

Обязателен только `camera.rtsp_url`. Все параметры описаны комментариями в
[config.example.toml](config.example.toml), неизвестные ключи и неверные значения отклоняются при
старте с понятным сообщением. Самое важное:

| Параметр | Что делает |
|---|---|
| `model.classes` | что сопровождаем: `["person"]`, `["person", "car"]` или `[]` (все классы) |
| `model.imgsz` | размер, до которого сжимается кадр: больше = видны дальние цели, но медленнее |
| `model.conf` | порог уверенности детектора: меньше = больше целей и больше ложных срабатываний |
| `model.device` | `cpu`, `cuda` или `cuda:0` |
| `tracking.confirm_hits` | сколько кадров подряд подтверждают цель перед захватом |
| `tracking.lost_timeout_sec` | через сколько секунд невидимая цель считается потерянной |
| `tracking.points_interval_sec` | как часто писать точку траектории |

Веса `yolov8n.pt` (около 6 МБ) при первом запуске ultralytics скачивает сам в директорию `models/`.

## Запуск

```
python main.py                    # с окном, выход по клавише q
python main.py --headless         # без окна, остановка по Ctrl+C
python main.py --config other.toml
python main.py --init-db          # создать базу и таблицы в ClickHouse и выйти
python main.py --list             # последние 20 событий из ClickHouse
python main.py --list 50
python main.py --self-test        # проверить PyTorch, ultralytics и модель
```

## ClickHouse

Для разработки в проекте есть `docker-compose.yml`:

```
copy .env.example .env
```

В `.env` необходимо задать пароль в `CLICKHOUSE_PASSWORD` и тот же пароль в
`REC_CLICKHOUSE_PASSWORD`: им программа подключается к базе. Программа сама читает
`REC_CLICKHOUSE_PASSWORD` из файла `.env` рядом с `config.toml`, задавать переменную окружения
отдельно не нужно. Порядок поиска пароля: переменная окружения, `.env`, `config.toml`. Затем:

```
docker compose up -d
python main.py --init-db
```

В `config.toml` в разделе `[clickhouse]` указать `username = "rec"` (пользователь из
`docker-compose.yml`). Для собственного сервера достаточно указать его адрес.
Таблицы создаются автоматически при первом запуске (`create_schema = true`), схема лежит в
[rectrack/schema.sql](rectrack/schema.sql). Все времена хранятся в UTC и соответствуют моменту
получения кадра, а не концу его обработки.

Таблицы на движке `ReplacingMergeTree`: если вставка оборвалась по таймауту, но сервер её
принял, повтор не удваивает данные навсегда, дубли схлопываются при слиянии частей. До слияния
они могут быть видны; для точного счёта к таблице добавляется `FINAL`
(`SELECT count() FROM rec.tracks FINAL`).

| Таблица | Что в ней |
|---|---|
| `events` | журнал: событие `captured` при захвате и `lost` при потере, со ссылкой на снимок |
| `tracks` | итог по каждой цели: время, длительность, число кадров, уверенность, пройденный путь, причина завершения |
| `track_points` | траектории: положение рамки не чаще, чем раз в `points_interval_sec`; хранятся 30 дней |

Номер цели от трекера (`track_id`) начинается заново при каждом запуске, поэтому для однозначной
ссылки есть `track_uid`, а запуск программы обозначает `session_id`.

Примеры запросов:

```sql
-- сколько людей было захвачено по дням
SELECT toDate(captured_at) AS day, count() AS targets
FROM rec.tracks WHERE class_name = 'person' GROUP BY day ORDER BY day;

-- кто дольше всего был в кадре сегодня
SELECT camera, track_id, duration_sec, snapshot
FROM rec.tracks WHERE toDate(captured_at) = today() ORDER BY duration_sec DESC LIMIT 10;

-- траектория одной цели
SELECT ts, (x1 + x2) / 2 AS cx, (y1 + y2) / 2 AS cy
FROM rec.track_points WHERE track_uid = '...' ORDER BY ts;

-- сколько целей находилось в кадре в течение каждого часа
SELECT toStartOfHour(captured_at) AS hour, count() FROM rec.tracks GROUP BY hour ORDER BY hour;
```

## Снимки

При захвате цели в директорию `capture/` пишется снимок с рамками и номерами:
`дд-мм-гггг-чч-мм-сс-класс-idN.jpg`, например `21-09-2026-14-03-27-person-id5.jpg`. Существующие
файлы не перезаписываются. Директория сама не очищается. Путь к снимку попадает в таблицы
`events` и `tracks`.

## Тесты

```
pip install -r requirements-dev.txt
ruff check .
pytest
```

Тестам нужен только numpy: torch, ultralytics, OpenCV и clickhouse-connect подключаются лениво и
заменены заглушками, время управляется вручную. Тесты рисования и кодирования JPEG пропускаются,
если OpenCV не установлен.

Тесты не обращаются к настоящему ClickHouse, камере и видеокарте: эти части проверяются только
при реальном запуске программы.

## Структура

```
rectrack/
  config.py      конфигурация (TOML): значения по умолчанию, проверка, пароль из окружения
  capture.py     чтение RTSP с переподключением, всегда самый свежий кадр
  detector.py    YOLOv8 + трекер (ultralytics), результат в виде списка целей
  tracks.py      жизненный цикл целей: захват, сопровождение, потеря
  recorder.py    что делать с событиями: снимок, запись в базу, журнал
  storage.py     буфер и пакетная запись в ClickHouse, схема
  schema.sql     таблицы ClickHouse
  snapshots.py   сохранение снимков
  overlay.py     рамки, номера и траектории на кадре
  pipeline.py    поток сопровождения
  app.py         командная строка, окно
tests/           тесты
docker-compose.yml   ClickHouse для разработки
```

## Ограничения

* Таймауты и длительности считаются по монотонным часам, поэтому перевод системного времени
  не ломает сопровождение; метки в базе берутся из системных часов.
* Трекер ведёт цели по положению и движению рамок, а не по внешности. Если люди тесно
  пересекаются или надолго скрываются, номера могут поменяться местами или смениться. Цель,
  вернувшаяся после `lost_timeout_sec`, считается новой. Опознавания людей по лицам в проекте нет.
* Значение `lost_timeout_sec` должно быть не меньше времени, которое ByteTrack помнит скрывшуюся цель
  (30 кадров, около 1-3 с). Если поставить меньше, цель, найденная снова под прежним номером, будет
  записана как новая.
* `ultralytics` по умолчанию отправляет анонимную статистику. Программа отключает её при
  загрузке модели (`sync=False`).
* В git не добавлять `config.toml`, `.env`, `models/`, `capture/`, `data/` и `venv/`: в первых
  двух пароли и адрес камеры, в остальных крупные и локальные данные.
